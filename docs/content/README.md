# 콘텐츠 발행 관리

키즐리 블로그의 발행 이력과 발행 계획을 관리하는 문서 묶음이다.
새 글을 기획하기 전에 **반드시 이 폴더를 먼저 확인한다.** 중복 주제 발행과 카테고리 난립을 막기 위해서다.

## 문서 구성

| 문서 | 내용 | 갱신 시점 |
|------|------|----------|
| [발행-완료.md](./발행-완료.md) | 발행된 글 전체 인벤토리와 메타데이터 | 글을 발행할 때마다 한 줄 추가 |
| [발행-예정.md](./발행-예정.md) | 후보 제목, 우선순위, 집필 전 검증 사항 | 주제를 새로 발굴하거나 발행이 끝났을 때 |

발행이 끝나면 해당 항목을 `발행-예정.md`에서 지우고 `발행-완료.md`에 옮긴다. 두 문서의 합이 곧 콘텐츠 전체 그림이다.

## 발행 워크플로

글 작성은 `content-creator` 스킬이 담당한다. 오케스트레이터가 아래 순서로 에이전트를 호출한다.

| Phase | 담당 | 산출물 |
|-------|------|--------|
| 1 | content-researcher | 키워드·출처 리서치 브리프 |
| 2 | seo-writer | 본문 초안 |
| 3 | image-director | HTML/CSS 이미지 → Playwright PNG 캡처 (1080×1080) |
| 4 | fact-checker | 출처 검증 보고서 |
| 5~6 | content-integrator | 최종 패키지 |
| 7 | — | **실제 발행** |

### Phase 7의 기계적 게이트

`.mdx`를 커밋하기 전에 반드시 아래를 실행한다.

```bash
npx velite build
```

이건 권장이 아니라 **필수**다. 과거 "육아기 근로시간 단축 제도" 글이 이스케이프하지 않은 `~`(범위 표기) 때문에 velite 컴파일에 실패해 목록에서 조용히 누락된 사고가 있었다. 자가 점검 체크리스트만으로는 걸러지지 않는다.

작업 폴더는 저장소 루트의 `_workspace/`이며 글마다 덮어쓰인다. 보존이 필요한 산출물은 이 `docs/content/`로 옮긴다.

## Frontmatter 스키마

`apps/web/velite.config.ts`가 강제하는 스키마다. 하나라도 빠지면 빌드가 깨진다.

| 필드 | 타입 | 필수 | 비고 |
|------|------|------|------|
| `uuid` | string | O | 글마다 고유값 |
| `title` | string | O | 제목 공식은 아래 참고 |
| `description` | string | O | 검색 결과 스니펫으로 노출된다 |
| `keywords` | string[] | | 기본값 `[]` |
| `category` | string | O | 아래 카테고리 체계 참고 |
| `tags` | string[] | | 기본값 `[]` |
| `publishedAt` | string | O | `YYYY-MM-DD` |
| `updatedAt` | string | | 제도·금액이 갱신될 때만 채운다 |
| `readingTime` | number | | 기본값 3 |
| `thumbnail` | string | O | `/blog/{슬러그}/thumbnail.png` |

`slug`와 `code`는 velite가 파일 경로와 본문에서 자동 생성하므로 직접 쓰지 않는다.
한글 파일명은 NFD를 NFC로 정규화해 슬러그로 쓴다.

## 카테고리 체계

카테고리는 5개다. 각각 부모의 서로 다른 질문 하나에 대응하며, 서로 겹치지 않는다.

| 카테고리 | 부모의 질문 | 글 수 | 포함 범위 |
|---------|-----------|------|----------|
| 양육 지원금 | 돈을 얼마나 어떻게 받나 | 7 | 부모급여·아동수당·양육수당·보육료·첫만남이용권과 이들 간의 관계 |
| 일·가정 양립 | 회사를 다니면서 어떻게 하나 | 4 | 육아휴직·근로시간 단축·출산휴가·맞벌이 제도 |
| 입소·등원 가이드 | 어린이집에 어떻게 들어가나 | 3 | 입소 절차·대기·우선순위, 입학 전 준비물과 서류 |
| 주거·생활 지원 | 집과 공과금은 어떻게 하나 | 3 | 대출·청약·공과금 감면 |
| 어린이집 생활 | 다니는 동안 무슨 일이 생기나 | 2 | 하루 일과·낮잠·급식·아플 때 대응 |

### 배치 기준

경계에 걸리는 글은 **상황이 아니라 답의 성격**으로 판단한다.

| 글 | 상황 | 답 | 배치 |
|----|------|-----|------|
| 어린이집 결석하면 보육료가 나오나 | 원 생활 | 보육료 지원 규칙 | `양육 지원금` |
| 아이가 아플 때 언제 다시 보내나 | 원 생활 | 등원 중지 기준 | `어린이집 생활` |
| 국공립 우선순위 가점 | 입소 준비 | 입소 순위 산정 | `입소·등원 가이드` |
| 맞벌이 가정 지원 제도 | 입소 준비 포함 | 고용·노동 제도 묶음 | `일·가정 양립` |

### 확장 계획

[발행-예정.md](./발행-예정.md)의 22편을 모두 발행하면 분포가 이렇게 된다.

| 카테고리 | 현재 | 예정 유입 | 합계 |
|---------|------|----------|------|
| 어린이집 생활 | 2 | +12 | **14** |
| 양육 지원금 | 7 | +3 | 10 |
| 입소·등원 가이드 | 3 | +7 | **10** |
| 일·가정 양립 | 4 | 0 | 4 |
| 주거·생활 지원 | 3 | 0 | 3 |

`어린이집 생활`과 `입소·등원 가이드`가 각각 두 덩어리로 부푼다. 지금 미리 쪼개면 빈 카테고리가 생기므로 5개를 유지하되, **아래 조건에 걸리면 그때 분할한다.**

| 분할 대상 | 조건 | 나눌 기준 |
|----------|------|----------|
| 어린이집 생활 | 10편 초과 | 원에서의 일상(낮잠·급식·배변·친구)은 `어린이집 생활`에 두고, 못 보낼 때(아플 때·대체 돌봄·방학)를 `돌봄 공백`으로 분리 |
| 입소·등원 가이드 | 8편 초과 | 들어갈 수 있나(절차·대기·우선순위)는 `입소·등원 가이드`에 두고, 들어간 뒤 준비(준비물·서류·적응)를 `입학 준비`로 분리 |

분할 후 예상 분포는 양육 지원금 10, 어린이집 생활 9, 입학 준비 7, 돌봄 공백 5, 일·가정 양립 4, 입소·등원 가이드 3, 주거·생활 지원 3으로 고르다.

### 카테고리를 바꾸면 무엇이 영향을 받나

거의 없다. 카테고리는 라우팅에 쓰이지 않는다.

| 대상 | 영향 | 근거 |
|------|------|------|
| 글 URL | **없음** | 경로는 `/contents/{슬러그}`이고 슬러그는 파일명에서 나온다 (`velite.config.ts`) |
| 내부 링크 | **없음** | 글 간 링크도 슬러그 기준이다 |
| sitemap.xml | **없음** | `/contents`와 `/contents/{슬러그}`만 등록한다 (`app/sitemap.ts`) |
| 구조화 데이터 | **없음** | `lib/structured-data/`가 category를 쓰지 않는다 |
| 카테고리 필터 칩 | **없음** | `ContentList.tsx`가 글 목록에서 동적으로 생성한다. 하드코딩된 목록이 없다 |
| `?category=` 쿼리 파라미터 | **있음** | 목록 페이지 필터가 nuqs로 URL에 값을 남긴다. 옛 카테고리명으로 된 링크는 필터가 안 걸린 채 전체 목록으로 뜬다 |

즉 실질 비용은 `?category=` 링크가 깨지는 것 하나뿐이고, 이것도 404가 아니라 **필터만 풀린 정상 목록**으로 뜬다. sitemap에 등록된 적이 없어 검색엔진이 색인했을 가능성도 낮다.

2026-08-17에 이 근거로 7개 카테고리를 위 5개로 재편했다. 다음에 또 바꿔야 한다면 같은 비용으로 가능하다.

## 집필 규칙 요약

상세는 `.claude/agents/seo-writer.md`와 `.claude/skills/content-creator/`에 있다. 자주 걸리는 것만 옮겨둔다.

### 제목

`키워드 + 후킹 − 군더더기` 공식으로 한글 30~40자에 맞춘다.

### MDX 이스케이프

물결표 `~`는 반드시 `\~`로 이스케이프한다. 범위 표기(`0\~2세`, `1\~3개월`)에서 가장 자주 터진다.

### 구글 2026 랭킹 기준 4개 축

1. **에버그린 주제 판정 + 갱신 데이터 층.** 제도·금액이 바뀌면 `updatedAt`을 채워 신선도 신호를 준다
2. **제목 공식** 준수
3. **해결형 프레임 강제.** 홍보형 톤은 불리하다. CTA는 "다음 행동 안내"로 쓴다
4. **완결성 우선.** 글 길이 상한은 없다. 구체 수치·조건별 분해·예외 케이스를 의무로 넣고, 정보 이득 포인트를 최소 2가지 확보한다

### 출처

모든 수치와 제도 내용에 인라인 출처를 단다. 정부 원문(보건복지부 보육사업안내, 고용노동부, 질병관리청 등)을 1차 근거로 쓰고, 블로그·언론 기사는 보조로만 쓴다.
